# brainmem：记忆库只算权重，其余全归 AI

**分工**：记忆库只负责**权重**（加权重、算衰减、清零自动遗忘）+ 边的权重规则。
**你（AI）负责其它一切**：拆分、简写、录入、**建立连接**、以及"睡觉整理"。

## 字数由你定，权重由库按字数算
每条记忆写几个字**由你自己判断**，库**只按字数给初始权重** `W0 = f(字数)`：
- **字数越少 → 权重越高 → 越难忘**；字数越多 → 权重越低 → 越易忘。
- 1–10 字：1字=8.00、3字=6.00、5字=5.00、8字=3.00、10字=1.00。
- 超过 10 字：继续单调下降（11字≈0.95、20字≈0.81、50字≈0.62，地板 0.10）。
- 所以：**想让它长存的，就写短、写到精髓**；细节、长句本就更快淡忘——符合设计。
- 唯一硬上限：单条 ≤ MAX_LABEL_CHARS（默认 100 字），防小作文。

## 记忆库给你的工具
| 工具 | 谁决定 | 作用 |
|---|---|---|
| `memory_ingest(atoms, text?, note_title?)` | 你拆好原子（字数你定） | 批量入库（不建边）；`text` 给了就另存一条原文冷存 |
| `memory_link(src, dst, relation)` / `memory_link_many(pairs)` | **你决定连谁** | 建边；权重由库给（不要传 weight） |
| `memory_search(query, use=True)` | — | 检索；**默认 use=True，命中的记忆自动 +权重、走过的边自动 +权重** |
| `memory_get(node_id, use=True)` | — | 取记忆详情；`use=True` 时也自动加权重 |
| `memory_reinforce(node_id)` | 你 | 手动给某条加权重（额外巩固时用） |
| `memory_simplify(node_id, new_text)` | 你 | 换成更简写法并加权重 |
| `memory_merge(ids, new_text, mode="soft")` | 你 | 多条合并成一个**父记忆**（标题=new_text）。**默认 soft（软合并）**：成员全保留、原文汇总进父节点、可展开可回滚。mode="hard" 才删成员。**⚠️ 前置条件：这几条之间必须已有强连接（边权≥8.00、共激活≥5、寿命≥365天），否则拒绝** |
| `memory_inspect/stats/explain` | — | 查询（含权重、衰减、事件流、关联） |

## 写入时怎么拆（你的裁量）
**只记"值得回忆"的**：
- **元叙述 / 纯感想**（"今天过得很普通""还是想写一写"）→ **直接跳过**；"今天"用记录日期代表，不专门写一条。
- **能合并就合并**：同一场景的连续动作合成一两句整话（不是一动作一条）。
  - 反例：`闹钟响`/`翻个身`/`又睡五分钟`/`妈妈喊`/`跳下床`/`刷牙洗脸`/`吃包子出门`
  - 正例：`六点钟起床差点迟到` / `吃了两个包子出门`
- **保留事实**：数字、比分、时间、地点、专有名词、关键结果。
- **每条留可降级内核**：想到"权重衰减后再简写会变成什么"。
  - `六点钟起床差点迟到` → `差点迟到`
- 字数**由你决定**（短=强、长=弱，见上）；不加装饰符号。

## 建立连接（也是你的事）
- 叙事先后 → `SEQUENCE`；同事件并列 → `ASSOCIATED`；因果 → `CAUSES`；从属 → `PART_OF`。
- 只连**确有语义关系**的，别为连线而连线。**不要传权重**，库会算。

## 用进废退（不再有"睡觉整理"）
记忆库没有"睡觉/整理"这套机制了。**强化是自动的、即时的**：
- **每次检索/取用记忆 → 命中的每条自动 +0.5 权重**（`memory_search` 默认 `use=True`，`memory_get(use=True)`、`memory_feedback` 同理）。
- **每次检索走过的连接 → 该边 +0.3 权重、共激活 +1**（等于"用到了连接就加强它"）。
- 所以**多用就多记牢、不用就衰减**——这才是仿脑的"用进废退"。你不需要专门"整理"。
- 你唯一需要主动做的，是**简写/合并**（当记忆内容该精简、该归并时）：
  - **简写**：`memory_simplify`，把变糊的长记忆压成更短内核（`六点钟起床差点迟到`→`差点迟到`）。
  - **合并**：`memory_merge(ids, new_text)`（默认 soft 软合并）——新建一个**父记忆**（短标题）挂在成员之上，成员全部保留、原文汇总进父节点，检索命中父标题后可展开看到"几条记忆连在一起"及完整原文；出错可 `merge_undo(batch_id)` 回滚。**⚠️ 合并有门槛**：这几条之间必须先有强连接
    （边权 ≥ 8.00 且 共激活 ≥ 5，且连接寿命 ≥365 天）。不够强就先用 `memory_link` 反复连接，
    达标后再合并；联系不强别硬合并。
  - 合并是**记忆长文本/可复原**的正道：父节点=短标题+汇总原文，既省上下文又能复原。
  - `memory_reinforce` 仍可手动给某条加权重（想额外巩固某条时用）。

## 标准流程
1. 读原文 → 按上面原则拆成 `atoms`（字数自定）。
2. `memory_ingest(atoms, text=原文, note_title=...)` 落库（要留原文就传 text）。
3. `memory_link_many([{src,dst,relation},...])` 建立你判断的连接。
4. 之后**正常检索/取用就是在强化**（自动加权重），无需专门整理。
5. 回报：写了几条、建了几条边、note 存没存。

## ⭐ 必须传 text：记忆要能"复原"，不能只剩骨架（2026-11-11 主人定）
原则：**atoms 负责"快速想起"，text 负责"能复原"。两者都要，缺一不可。**

- **每次 `memory_ingest` 都要传 `text`（完整原文）**，标题用 `note_title`。
  - `text` 会经 `write_note(title, full_text)` 存成"标题入库 + 原文进冷存(blob)"。
  - 关键：记忆降档（压缩/遗忘）时**原文仍在冷存里，不会被删**；升档时还能从冷存回挂原文。
  - 所以哪怕 atoms 只有几个字、哪怕权重衰减到 0，**完整原文永远能回查**。
- **text 的要求：写"能复原当天事情"的程度即可，不必逐字。**
  - 好：一段通顺的话，讲清"哪天、和谁、做了什么、结果如何、关键数字/名字"。
  - 不必：每一个语气词、每一句闲聊原封不动。
  - 目标：**别人（或未来的我）读这段 text，能重建当时发生了什么。**
- **atoms 照旧压到 10 字以内**（短=权重高=难忘）；它只是索引，不是内容。
- **日志（logs/YYYY-MM-DD.md）继续写、写详细**——主人要看，且是真相源。
- 一句话记牢：**atoms 是书脊上的书名，text 是整本书，日志是图书馆。三层都要。**

## 🧹 归零清理（自动遗忘）
- 记忆权重随时间衰减，**衰减到 0 会自动物理删除**（连边一起删、原文冷存也清）——这是"真正的遗忘"。
- **自动执行**：Windows 计划任务 `brainmem-sweep-daily` 每天 03:00 跑一次 `sweep --apply`，日志在 `logs/sweep.log`。
- **手动预览**：`python -m brainmem.interfaces.cli sweep`（默认 dry-run，只列"将删清单"，加 `--apply` 才真删）。
- MCP 工具 `memory_sweep(dry_run=True)` 同样可用（DSH 重启后暴露）。
- 不做实时刷新：只有"归零"这一件事会被处理，没归零的记忆一个字节都不动。
